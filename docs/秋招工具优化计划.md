# 求 offer 本地秋招工具优化计划

> 状态：阶段 A 已于 2026-08-13 完成并通过隔离验收；阶段 B–D 保留为后续路线，不在本轮自动展开。

## 1. 目标

在保持纯本地、现有数据可继续使用、状态与进度仍由用户掌控的前提下，先修复会影响投递判断的业务口径，再缩短日常记录和查找路径，最终让工具真正帮助用户做到：不漏截止时间、不记错岗位、每天知道该推进什么、复盘后能调整投递策略。

## 2. 产品边界

- 继续使用本地 JSON、图片资产和自动快照，不引入数据库、账号、云同步或团队权限。
- 不自动登录招聘网站，不自动修改投递状态，不做验证码或邮件抓取。
- 不删除或重解释用户已经填写的状态、进度、时间线和备注。
- 状态与进度继续区分；时间线只提供同步建议，未经用户确认不覆盖手填内容。
- 修改数据结构时必须兼容旧记录；升级前后均能读取现有工作区。
- 每一阶段单独测试和验收，关键修复未稳定前不堆叠大型新功能。

## 3. 当前基线

- 主工作区、图片和快照保存在 `%LOCALAPPDATA%\Offer-AutumnRecruitment`。
- 当前测试：34 项通过；生产构建通过；浏览器未发现控制台错误。
- 总表、岗位目录、甘特图和日历已有分页或折叠，约 100 条投递无需数据库或全局虚拟列表。
- 主要风险不在数据量，而在业务口径、时间规划一致性、节点关联和高频操作效率。

## 4. 分阶段实施

### 阶段 A：业务正确性与防误操作（已完成）

1. 修复“待投递”被识别为“已投递”。
2. 未来投递节点在到期前不计入已投递和分析统计。
3. 将“用户编辑时间”和“招聘流程活动时间”分开，避免改重视程度或行动后等待天数归零。
4. 将签约、入职正确计入历史 Offer 到达结果。
5. 处理手填进度与时间线阶段不一致：保留手填值，同时明确展示可采纳的时间线建议。
6. 日历颜色按事件类型表达，图例与实际语义一致。
7. 甘特图和日历共用岗位筛选，默认排除已结束岗位，可手动包含。
8. 新增节点默认使用当前岗位；无当前岗位时必须明确选择，不再静默使用第一条记录。
9. 公司别名改为安全匹配，避免“京东方”被归为“京东”。

验收标准：

- 为上述业务边界补充自动化测试。
- 现有 34 项测试继续通过，新增测试全部通过。
- 使用隔离数据完成“待投递、未来投递、一面、签约、结束岗位、同日多节点”浏览器回归。
- 不写入或修改用户真实工作区数据。

实际结果：57/57 自动化测试通过，生产构建通过；使用 4174 端口与独立临时目录完成浏览器回归；真实工作区仍为 3 条岗位、4 个时间节点、7 份备份，修订和 SHA-256 均与本轮开始前一致。

### 阶段 B：统一记录进展与日常推进

1. 将现有时间节点入口升级为统一“记录进展”：事件、发生时间、结果、状态、进度、下一步和 DDL 可在一次操作中完成。
2. 保存前展示将要同步的字段；用户可取消单项同步。
3. 首页、总表、岗位页和时间规划使用同一入口并自动刷新所有视图。
4. 已结束岗位出现未来节点时，提供能直接定位并处理节点的入口。

验收标准：一次记录后首页、总表、岗位流程、甘特图、日历和分析口径一致；刷新后保持一致；用户手填值不会被静默覆盖。

### 阶段 C：大量投递下的使用效率

1. 总表增加按 DDL、重视程度、最近更新和投递时间排序。
2. 增加“本周要办、重点待投、7 天无进展、已结束”等快捷视图和一键清筛。
3. 保留总表与时间规划的筛选、排序、页码和显示岗位状态。
4. 首页阶段区保持摘要，查看全部时跳到带条件的总表，不无限拉长首页。
5. 时间规划增加岗位搜索和“仅活跃、仅高优先级、包含已结束”快捷条件。

验收标准：用不少于 100 条合成记录验证分页、筛选、排序、返回状态、空结果和性能；不触碰真实数据。

### 阶段 D：可读性、本地可靠性与维护清理

1. 修复键盘焦点、页签语义、表格语义和搜索可访问名称。
2. 关键文字不小于 12px，次要文字不小于 11px；改善小窗口和分屏布局。
3. 快照支持查看全部并使用可靠创建时间；导入校验岗位 ID 唯一。
4. 为未引用图片提供只读扫描和明确确认后的清理入口。
5. 清理未接入的半成品页面、无效按钮、旧样式和约 52.8MB 的遗留字体。
6. 移除与 Windows 纯本地定位不一致的 macOS/Sites 发布遗留，增加构建版本指纹，防止快捷方式启动旧构建。

## 5. 后续功能池（不纳入当前 Goal）

- 多行动列表与完成历史。
- 互联网、国企/央企、事业单位/泛体制、自定义流程模板。
- 十秒快速收录和重复岗位提醒。
- 跨岗位面试复盘库与薄弱项转行动。
- 投递简历、作品集和求职信版本记录。
- 结束原因分析、Windows 本地提醒、CSV 导入导出。
- Offer 决策对比、秋招季归档、每周复盘摘要。

## 6. 暂不建设

- 账号系统、远程数据库、云同步、多人协作。
- 自动登录、验证码处理、自动投递或自动改状态。
- 完整邮件/微信/日历 OAuth、完整联系人 CRM。
- 通用 AI 聊天页以及与现有五个核心页面重复的新页面。

## 7. 交付与回滚原则

- 每个阶段开始前记录基线；完成后执行测试、构建和浏览器回归。
- 测试使用临时数据目录或前端隔离数据，禁止拿真实工作区做破坏性试验。
- 数据格式变化必须有兼容迁移与回归样例；失败时保持旧数据只读可用。
- 每批改动保持小而可审查；发现影响现有使用体验时优先回退该批，而不是继续叠加修补。
- 本地验收完成后先交付变更摘要；未经再次确认不主动推送 GitHub 或发布新版本。
